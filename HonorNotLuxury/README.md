# Honor, Not Luxury 2.0 — 荣誉贵族

[English](README.en.md)

我是叮咚，也是这个 Mod 的作者。玩 RimWorld 时，我想保留贵族头衔带来的身份与权益，却不想让头衔强制要求奢侈生活。我找过现有 Mod，没有找到足够贴近这一需求的方案，于是提出了 Honor, Not Luxury 的想法，先为自己的存档制作，现在公开给有同样需求的玩家使用。它为 RimWorld 1.6 的爵位生活要求提供分项、分范围豁免；默认只调整玩家的正式殖民者。

需要 **Royalty DLC 与 Harmony**。OA 金鸢尾兰不是硬依赖；使用原版 `RoyalTitleDef` 需求机制的 OA 头衔走同一套规则。

这个 Mod 的需求、功能取舍和适用范围由我提出并决定，**代码由 AI 编写**；我负责审阅代码、在游戏内测试并维护项目。截至 2026-09-27，我已在自己的 **140+ Mod 环境**中确认它可加载、设置菜单可用；卧室、谒见厅、服装款式与品质、食物和期望等选项可以分别调整，切回“保持原有机制”后相应的负面心情会重新出现。这说明上述功能在我的环境里有效；并不代表它与所有 Mod 兼容。该环境本身存在其他日志警告和异常，因此这里所说的运行验证是**未观察到由本 Mod 引起的新增报错**，不是整份游戏日志没有报错。

## 设置与默认行为

入口：**选项 → Mod 设置 → 荣誉贵族**（英文：Honor, Not Luxury）。设置使用 RimWorld 自带配置系统，关闭游戏后保留，对所有存档通用。

| 独立选项 | 默认 | 豁免内容 |
|---|---|---|
| 爵位卧室要求 | 仅正式殖民者免除 | 爵位要求的个人卧室、面积、豪华度、家具和相应负面心情 |
| 日常谒见厅要求 | 仅正式殖民者免除 | 平日爵位要求的王座、房间规格及相应负面心情 |
| 贵族服装款式 | 仅正式殖民者免除 | 没有指定贵族服装的负面心情 |
| 贵族服装品质 | 仅正式殖民者免除 | 服装品质不够的爵位负面心情 |
| 爵位饮食要求 | 仅正式殖民者免除 | 爵位导致的拒食、新产生的食物不合身份记忆及相关缺食警报 |
| 爵位最低期望 | 仅正式殖民者免除 | 爵位抬高的期望下限；继续使用原有财富、文化职位和宽限期计算 |
| 爵位工作限制 | 保持原有机制 | 可选：仅去掉爵位造成的工作限制 |

**每一行都有三个选项：**

- **保持原有机制**：本 Mod 不干预这一项，继续采用原版及其他 Mod 的判定。
- **仅正式殖民者免除**：玩家阵营的人类级角色，排除访客、任务临时成员、囚犯、奴隶和原版认定的非人类化突变者。外出成员、精神崩溃中的正式成员仍在范围内；不以当前位置或是否可操控为条件。
- **所有角色免除**：对拥有原版 Royalty tracker 的所有角色应用这一项豁免，包括非玩家角色。

“保持原有机制”不会强迫原版没有要求的 NPC 获得新要求。例如，原版日常谒见厅检查本来就只针对特定殖民者，食物警报也不是对全世界 NPC 显示；本 Mod 保留这些边界。

## 保留的机制

- **授勋仪式及其谒见厅规格验收完全保留**，包括面积、豪华度、家具等原有门槛；不仅是留下一张王座。各头衔是否需要场地由原任务决定。
- 爵位名称、等级、荣誉值、许可、灵能、继承、外交、贸易与既有授勋任务。
- 普通房间环境心情、普通饮食规则、文化服装禁忌，以及财富和文化职位导致的期望。
- 工作开关不会清除背景、特性、健康、基因、文化职位或任务造成的其他工作限制。同一种工作同时被爵位和其他来源禁止时，其他来源继续生效。
- 敕令、自大标志、贵族娱乐规则，以及 NPC 的服装生成规则。不开“清除 conceited”的总开关。
- 已建造谒见厅本身的无效布局提示，以及授勋任务提供的要求文字，可能依旧显示；日常心情豁免不删除建筑和任务的全部说明。

## 安装

1. 关闭 RimWorld。将 `HonorNotLuxury` 文件夹放入游戏的 `Mods` 目录。
2. 启用 Harmony、Royalty 和本 Mod；让本 Mod 排在 OA 模组链及其他需求修改 Mod 之后。
3. 进入 Mod 设置确认各行范围。已有存档可直接读入；首次验收建议使用存档副本。

项目/发布包根目录还提供安装脚本，可在 PowerShell 中执行：

```powershell
# 预览，不写文件
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -WhatIfOnly

# 复制运行文件并在 ModsConfig.xml 中启用
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

其他安装位置使用 `-RimWorldDir "D:\Steam\steamapps\common\RimWorld"`；使用自定义存档配置目录时指定 `-ConfigPath "完整路径\ModsConfig.xml"`。

脚本先验证源文件和 XML，再复制 `About`、`Assemblies`、`Languages`、中英文说明与许可证。已安装的旧文件夹备份到游戏目录的 `HonorNotLuxury-backups`，不放在 `Mods` 内，避免被游戏重复发现；修改配置时创建带唯一时间戳的 `.bak`。配置写入失败会回滚已安装文件夹。包 ID 不区分大小写去重，并统一为 `local.honornotluxury`，排在启用列表最后。备份文件不会被重复安装覆盖；更新已经关联工坊项目的本地文件夹时，若新包未自带 ID，还会保留原有 `About/PublishedFileId.txt`。

开发阶段的受控 QA 没有代替游戏内测试；上面的实测结果来自后续实际游玩。安装脚本的自动化测试使用隔离的假游戏目录，不会修改用户的真实存档。

## 中途加入、切换、移除

支持中途加入。本版本只拦截运行时判定，不增添需要保存在角色上的自定义组件，不改写 `allowRoomRequirements`、`allowApparelRequirements` 或 `RoyalTitle.conceited`，不删改 Def。

设置改变后会刷新角色工作限制和情境心情缓存，后续判定采用新范围。已有食物负面记忆按原持续时间自然消退。新开放的工作可能需要手动分配优先级；切回原机制也不重建你此前的工作安排。成员加入、离开或结束临时任务后按当前身份重新判定。

可以中途移除：在 Mod 列表停用本 Mod 并重启游戏；若某个管理器没有移除启用条目，应同时移除 `local.honornotluxury`。本版本没有永久写入豁免标志，原规则会重新参与计算。原生 Mod 设置文件可保留，不影响读档。设置切回“保持原有机制”后的恢复已在游戏中验证；**完整的停用、重启、读档流程仍应在存档副本上先做一次**，尤其是同时使用其他爵位修改 Mod 时。

**旧原型例外：**如果某个存档曾在原始 1.x 版本启用期间保存，里面可能已经有被旧版写为 `false` 的要求字段或自大标志。2.0 不猜测这些值的来源，也不会一律强制改回 `true`，因此不会自动修复旧原型造成的残留。最好使用启用原型前的备份；如需修复已有残留，应另行针对存档核对。单纯曾启用但未保存，不会污染磁盘上的原存档。旧自定义 `Config/HonorNotLuxury.xml` 不再读取，使用本版设置界面重新选择。

## 游戏内验证与剩余检查

2026-09-24 的受控 QA 针对本机 RimWorld `1.6.4871`、`Assembly-CSharp 1.6.9676.17735` 和已安装 Harmony 构建。详细结果见 [受控 QA 报告](Docs/QA_V2_REPORT.md)；那份报告记录的是**开发当时的状态**。之后的人类实机验证已确认 Mod 识别、设置界面、分项切换及原规则恢复。

受控测试覆盖作用范围、临时成员、真实服装心情与食物判定、食物警报候选混排、文化职位期望、工作缓存与重叠限制、授勋验收入口、设置序列化及存档字段往返。**尚未声称完整验证所有头衔、访客与 OA 许可组合、整套授勋流程，以及与每个已安装 Mod 的交互。**

建议用有实际需求的头衔做以下验收；自由民等没有相应门槛的低阶头衔，本来就不会显示变化：

1. 打开中/英文 Mod 设置，检查七行下拉菜单可读，切换与重开游戏后设置保留。
2. 同图放置正式殖民者与有要求的任务访客，确认默认只豁免前者；分别验证“保持原有机制”和“所有角色免除”。
3. 给拥有文化职位的贵族检查期望；职位带来的期望增加仍应存在。打开工作豁免后检查背景/健康等来源的限制仍在。
4. 启动原版及 OA 授勋任务，确认不合格场地仍被拒绝，合格场地能完成仪式，荣誉/头衔/许可正常。
5. 在测试存档另存后停用本 Mod、重启并重读，确认相应要求恢复，且无缺失自定义 Def 错误。

正常启动日志：`[Honor, Not Luxury] 2.0 active: seven scoped policies; bestowing requirements preserved.`

若游戏更新使目标方法不匹配，或 Harmony 挂载失败，本 Mod 会撤销自己的补丁并在日志和设置窗口提示；不会继续只应用一半功能。任何其他 Mod 直接替换整段需求逻辑仍需单独检查，不能仅凭使用 Harmony 宣称全面兼容。

## 构建与实现

源码在项目的 `HonorNotLuxury/Source`。目标 `net472`，构建会把本 Mod DLL 复制到 `HonorNotLuxury/Assemblies`，不打包游戏或 Harmony DLL：

```powershell
dotnet build .\HonorNotLuxury\Source -c Release
```

项目根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1` 可生成只包含审阅过的运行文件、源码和文档的发布包，并校验包内哈希。工坊发布前的步骤见项目内的 `PUBLISHING.md`。

可用 `-p:RimWorldDir=...` 和 `-p:HarmonyDir=...` 覆盖引用位置。不要同时启用原型 DLL 和 2.0 DLL。

12 个补丁类覆盖 16 个游戏方法。卧室/谒见厅/食物采用按角色过滤的后置补丁；服装心情采用按角色过滤的前置补丁；期望、食物警报和工作来源只替换指定方法中对 `RoyalTitle.conceited` 的一次读取。替换要求精确匹配一次，保留其余原版流程及 IL 标签。工作类型和工作分配器的缓存入口会检查身份/范围变化。补丁不会临时写入共享 Def 或原版角色字段。
