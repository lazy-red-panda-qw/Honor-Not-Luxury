## 执行环境与边界

游戏目录的 `Version.txt`：`1.6.4871 rev590`；用户现有配置记录 rev591；当前实际 `Assembly-CSharp.dll` 程序集版本：`1.6.9676.17735`。本次以实际程序集为编译和行为验证依据。Harmony 使用已安装工坊 `2009463077/Current/Assemblies/0Harmony.dll`。

运行器通过 [Mono 官方嵌入 API](https://www.mono-project.com/docs/advanced/embedding/) 启动游戏目录中的 `mono-2.0-bdwgc.dll`，加载原游戏托管程序集。**未修改游戏 DLL。**替代 Unity 日志和持久目录服务，手工构造最小角色、派系、地图、任务与文化职位数据；配置和序列化结果只写在 `_qa/v2/fixture`。食物警报测试另用受控食物搜索替身，不替换被测的警报遍历或爵位食物方法。

早期用系统 .NET Framework 与 .NET 9 做烟测时分别遇到游戏依赖 API 和 Harmony 运行时不兼容，最终验证统一改为游戏自带 Mono；这些早期宿主错误不作为游戏环境或发布 DLL 的缺陷。最终 `behavior.log` 没有这些错误。

这些结果不能替代完整实机联调。未验证设置窗口的实际字体、滚动和分辨率表现；未在实际存档中走完整的 OA/原版授勋流程；未同时加载整套 OA 与其他 Mod 的 Harmony 补丁。因此“OA 适用”的依据是其使用的原版需求路径和本机静态调查，不是已完成整套环境的实机认证。背景、健康、基因等工作来源的保留主要由限定修改爵位分支的代码审查支持，本轮重叠行为用文化职位验证。

工作开关可能改变工作优先级，这是原版工作限制刷新带来的实际安排变化；关闭或移除 Mod 不会自动还原此前手动工作表。已有食物负面记忆自然到期。旧原型污染的存档不会被新版本自动修复。详见 `HonorNotLuxury/README.md`。

## 重现

在项目根目录：

```powershell
dotnet build .\HonorNotLuxury\Source -c Release
dotnet build .\_qa\v2\BehaviorTests -c Release
python .\_qa\v2\run_mono.py .\_qa\v2\BehaviorTests\bin\Release\net472\BehaviorTests.exe
powershell -NoProfile -ExecutionPolicy Bypass -File .\_qa\v2\TestInstaller.ps1
```

测试项目引用路径针对本机，可自行修改；运行器支持 `RIMWORLD_DIR` 环境变量。主 Mod 项目支持 `RimWorldDir` / `HarmonyDir` MSBuild 参数。不要把 `_qa`、`_recon`、游戏程序集或原型 DLL 复制进已启用的 Mod。
